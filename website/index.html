Zero Compromise Architecture

Built for Sovereign Privacy

Every layer of CryptoNote is engineered with defense-in-depth security invariants. No third-party trackers, no analytics SDKs, and zero telemetry.

Zero-Knowledge E2EE

The server never sees plaintext, titles, tags, or unencrypted keys. Even if the database is dumped or the host is seized, note contents cannot be decrypted.

Dual-Zone Notes & Vault

Separate your daily ideas from ultra-critical secrets. The Vault zone obscures titles in previews, requires dedicated biometric authentication, and enforces aggressive auto-lock.

Offline-First Engine

Write, edit, and search completely offline. Outbox queue pairs note changes in atomic Room transactions and pushes sequentially on reconnect with exponential backoff.

Deterministic Conflict Forking

No silent data loss or arbitrary "last-write-wins". Conflicting multi-device edits are cleanly forked into independent encrypted notes for side-by-side user resolution.

Anti-Forensic Hardening

FLAG_SECURE blocks screenshots, screen recording, and task-switcher previews. Automatic 60-second clipboard wipe and in-memory zeroization on vault lock.

Material 3 Dynamic UX

High-contrast Obsidian dark mode and crisp crystal light mode compliant with WCAG AA. Live Markdown editing, tag filters, and 7 vibrant accent palettes.

Zone Separation

Two Zones. Two Security Profiles.

CryptoNote intelligently splits your workflow into daily note-taking and ultra-hardened vault protection with distinct cryptographic lifecycle behaviors.

Daily Notes Zone

Fast, Fluid Encrypted Notes

Designed for meeting minutes, journal entries, code snippets, and daily checklists with instantaneous biometric unlock and fast tag filtering.

  • Instant Search: Full-text client-side encrypted search with zero server latency.
  • Markdown & Tags: Headers, bullet points, checklists, and color tags.
  • Seamless Sync: Atomic sync pushed in the background upon connectivity.
Hardened Vault Zone

Maximum Anti-Forensic Defense

Reserved for seed phrases, private keys, financial credentials, medical records, and legal archives. Zero digital footprints left in RAM.

  • Obscured Previews: Titles & excerpts blurred until biometric tap.
  • Memory Zeroization: Plaintext & master keys wiped via Arrays.fill(bytes, 0).
  • 60s Auto-Lock & Clipboard Shredder: RAM cleared after 1 min idle.
Cryptographic Specification

Envelope V1 & Key Hierarchy

Authentication is completely decoupled from Encryption. Changing your account login password never requires re-encrypting existing notes.

Binary Envelope Specification (V1)

Every encrypted note payload adheres to this strict, zero-overhead binary specification:

Field Byte Size Value Cryptographic Purpose
Format Version 1 Byte 0x01 Envelope binary version discriminator
Cipher ID 1 Byte 0x01 Designates AES-256-GCM cipher suite
Key ID 8 Bytes HKDF-SHA256 First 8 bytes of key identifier header
Nonce (IV) 12 Bytes CSPRNG Cryptographically random per-note initialization vector
Ciphertext Variable Encrypted JSON Encrypted title, body, tags, and client timestamps
GCM Auth Tag 16 Bytes 128-bit MAC Authenticated Additional Data (AAD) integrity tag

Adversarial Threat Model & Defenses

Server Database Dump ✓ Mitigated

Server only stores opaque binary blobs and SHA-256 hashes. Without the client-side master key derived via Argon2id, the dumped database is mathematical gibberish.

Rogue Cloud Admin ✓ Mitigated

Admins cannot forge or modify notes: AES-GCM AAD verifies UUID + Version. Any ciphertext alteration causes authentication tag validation failure on the client.

Device Theft / Physical Seizure ✓ Mitigated

Local database is encrypted with SQLCipher. Vault keys are zeroized in RAM (`Arrays.fill(bytes, 0)`) on lock, and Android Keystore StrongBox hardware isolates master keys.

Spyware / Screen Grabbers ✓ Mitigated

Window `FLAG_SECURE` prevents rogue background apps from recording or taking screenshots. Android OS task switcher shows a redacted blank canvas.

Yes! The backend is 100% open-source, written in TypeScript with Fastify and PostgreSQL. You can deploy it to Fly.io, Render, or run it via Docker Compose on your own home server or VPS. Simply point the Android client's backend URL in Settings to your self-hosted instance.

Authentication and Encryption are strictly decoupled. Your login password authenticates against the server (using Argon2id hash). Your Master Key, however, is generated locally via CSPRNG and wrapped by a Key Encryption Key (KEK). This allows you to change your server login credentials at any time without having to re-encrypt every note in your vault.

During account creation, CryptoNote generates a 256-bit mnemonic Recovery Key. If you forget your passphrase, this recovery key can unwrap your Master Key. If you lose both your passphrase and recovery key, no one—not even the project maintainers—can decrypt your notes.
